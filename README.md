Multi-Agent ด้วย Google ADK เพื่อวิเคราะห์บุคคลหรือเหตุการณ์ทางประวัติศาสตร์อย่างเป็นกลาง โดยใช้แนวคิด “ศาลจำลอง (Historical Court)” ซึ่งแบ่งบทบาทของ Agent ออกเป็นฝ่ายต่าง ๆ ได้แก่ ผู้ตั้งคำถาม นักวิจัยฝ่ายสนับสนุน นักวิจัยฝ่ายคัดค้าน ผู้พิพากษา และผู้สรุปคำตัดสิน

ระบบมีเป้าหมายเพื่อ:
รวบรวมข้อมูลเชิงบวกและเชิงลบอย่างเป็นระบบลดอคติจากมุมมองด้านเดียว แสดงให้เห็นกระบวนการคิดเชิงโครงสร้างผ่าน Agent หลายตัว
ระบบนี้ใช้แนวคิด
Separation of Roles: แต่ละ Agent มีหน้าที่ชัดเจน ไม่ซ้อนทับกัน
Parallel Research: การค้นหาข้อมูลเชิงบวกและเชิงลบทำพร้อมกัน
Iterative Review (Loop): มีผู้พิพากษาตรวจสอบความสมดุลของข้อมูล
State-based Reasoning: ทุก Agent ทำงานผ่าน shared state กลาง

รายละเอียดของ Agent แต่ละตัว
1. Inquiry Agent (รับหัวข้อ)
ตรวจสอบว่าใน state มี topic อยู่แล้วหรือไม่
หากมี → จบการทำงานทันที
หากไม่มี → ขอให้ผู้ใช้ระบุชื่อบุคคลหรือเหตุการณ์ทางประวัติศาสตร์ 1 รายการ

จุดเด่น
ป้องกันการตั้งหัวข้อซ้ำ
ควบคุม flow ตั้งแต่ต้นระบบ

Tool ที่ใช้
set_topic

2. Positive Researcher (ฝ่ายสนับสนุน)
วิเคราะห์ข้อมูลเชิงบวกของหัวข้อ
ใช้แนวคิดการค้นหาจาก Wikipedia เช่น achievements, contributions, legacy สรุปข้อมูลเป็นข้อความเดียว

ผลลัพธ์
บันทึกข้อมูลลงใน pos_data (list ใน state)

Tool ที่ใช้
append_list

3. Negative Researcher (ฝ่ายคัดค้าน)
วิเคราะห์ข้อมูลเชิงลบหรือข้อโต้แย้ง ใช้แนวคิดการค้นหา เช่น controversy, criticism, failure สรุปข้อมูลเป็นข้อความเดียว

ผลลัพธ์
บันทึกข้อมูลลงใน neg_data (list ใน state)

Tool ที่ใช้
append_list

4. Research Team (Parallel Agent)
รัน Positive Researcher และ Negative Researcher พร้อมกัน
เพิ่มประสิทธิภาพและลดเวลาในการวิเคราะห์

ใช้ Parallelเพราะข้อมูลสองฝั่งเป็นอิสระต่อกันสอดคล้องกับแนวคิดการพิจารณาคดีที่มีทั้งฝ่ายโจทก์และฝ่ายจำเลย

5. Judge Agent (ผู้พิพากษา)
ตรวจสอบความสมบูรณ์ของข้อมูลใน state
หากข้อมูลฝั่งใดฝั่งหนึ่งยังไม่มี ให้เติมข้อความ placeholder
เมื่อตรวจสอบแล้ว ให้สั่งออกจาก loop

ทำหน้าที่ควบคุมคุณภาพเป็นตัวตัดสินว่าข้อมูลเพียงพอหรือยัง

Tool ที่ใช้
exit_loop

6. Loop Agent (Court Loop)
ควบคุมการทำงานซ้ำของกระบวนการวิจัยภายในประกอบด้วย Research Team และ Judge

คุณสมบัติ
รองรับการทำงานแบบ iterative
สามารถขยายในอนาคตให้ Judge สั่งค้นใหม่ด้วย keyword ที่เฉพาะเจาะจงมากขึ้น

7. Verdict Agent (คำตัดสินสุดท้าย)
เขียนรายงานเชิงวิชาการอย่างเป็นกลาง
ใช้ข้อมูลจาก pos_data และ neg_data เท่านั้นไม่ค้นข้อมูลเพิ่มเติม


การจัดการ State
State ทำหน้าที่เป็นศูนย์กลางข้อมูลของระบบ โดยมี field หลัก ได้แก่:
topic : หัวข้อที่ผู้ใช้กำหนด
pos_data : รายการข้อมูลเชิงบวก
neg_data : รายการข้อมูลเชิงลบ
Agent ทุกตัวอ่าน–เขียนข้อมูลผ่าน state เดียวกัน ทำให้สามารถสื่อสารกันได้โดยไม่ต้องเรียกกันโดยตรง
